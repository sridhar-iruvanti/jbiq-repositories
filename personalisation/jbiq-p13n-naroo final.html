Personalized experiences
in JioBharatIQ
JioBharatIQ is India's daily AI companion, built for voice-first, multilingual, Bharat-scale use. Among its defining advantages is the ability to personalize to the individual — drawing on Jio's reach, distribution, and data signals to know each user with a depth and immediacy that compounds over time. This document covers the opportunity, the full canvas of personalization dimensions, how it plays out for a real user, and how we sequence execution.

1 · The Opportunity
Personalization as a
differentiated advantage
Jio's subscriber base, unified customer profile, device and SIM data, and regional reach create a foundation for knowing users that most AI assistants do not have access to. JioBharatIQ's personalization stack is designed to use that foundation from the first session, and to deepen it with every interaction.
What's available from the start
Meaningful signals before the first interaction
Language, device tier, household context, location, subscriber profile — available at first open. The assistant starts with context. No setup screen. No language picker. No blank slate.
What builds over time
Behaviour and memory turn a profile into an individual model
As the user interacts, JioBharatIQ learns how they phrase things, what they return to, when they use it, and what they skip. Over time the model stops serving a profile and starts serving a person.
The reach and distribution angle
500M subscribers, 12 languages, every device tier
Personalization at this scale means designing for diversity — across language, literacy, device, region, and household structure. The same precision that works for Sunita in Varanasi must work for a user in Kochi on a different device in a different language.
The destination
N=1: the experience is built for this person, not their segment
N=1 is a measure of precision. At the individual level, JioBharatIQ operates on what this user — only this user — has shown it. Not their demographic. Not their city. Them.

and dimensions
Personalization in JioBharatIQ operates across four categories: the signals that inform the model, the surfaces through which it is delivered, the interaction surfaces within the app experience, and the dimensions across which the experience is shaped. The items below are a strong, focused set — not an exhaustive inventory.
Signals — what informs the model
Active on first open · No input required
Ambient
Time of day
Morning greeting differs from late-night. Tone, task suggestions, and TTS behavior all shift.
Day and week
Weekday school prep vs weekend household tasks. Monday vs Friday changes what's contextually relevant.
Season
Summer heat, monsoon, Diwali prep, harvest season — JioBharatIQ knows what time of year it is and responds accordingly.
Location (pincode)
Regional language preference, local content relevance, city vs rural context. Varanasi is different from Kochi.
Regional calendar
Local holidays, exam cycles (UP Board schedule differs from CBSE), harvest festivals, state-level events.
Network and time zone
2G vs 5G shapes response density. Time zone ensures greetings and scheduling are locally accurate.
Active on first open
Device and SIM
SIM language — sets the default language without asking. Hindi SIM, Hindi JioBharatIQ.

Device tier — price range drives voice-first vs text, TTS auto-play, response brevity, image quality thresholds.

Device model — screen size, OS version, capability flags inform what the app can render and how.

Network type — 2G vs 4G vs 5G adjusts output density and media choices silently.
Active on first open
Jio Profile (UCP)
Identity — name, preferred language, account type. JioID resolution at first open.

Occupation — homemaker, farmer, student, small business owner. Drives starter prompt buckets.

Household — composition signals (senior member, children, household size). Shapes context for health, education, and grocery queries.

Location — night city, pincode. Regional precision for content and seasonal cards.

Service mix — which Jio services the user is active on. Signals lifestyle and usage patterns.
Builds with every interaction
In-session behaviour
Vocabulary and query length — simple short queries vs detailed formal ones. Maps to literacy calibration.

Speech rate and utterance length — fast, terse voice = brevity mode. Slow, detailed = elaboration mode.

Code-mix pattern — which languages blend, in what ratio. Register mirroring fires from Turn 1.

Sentiment — distress signals in voice or text trigger acknowledge-first response mode.

Tools used so far — what the user has engaged with this session shapes follow-up suggestions.
Ambient, Device, and UCP are active on Day 1. In-session behaviour accumulates within a session. All signals have fallback paths for non-Jio users — no blank slate in either case.
Memory — what persists and compounds
Active within the session
In-session context
The active conversation buffer — what has been said in the current session. Held in working memory, not persisted when the session ends.

last_topic, last_intent, incomplete_task_state — these are available to JioBharatIQ throughout the session to hold the thread and avoid repetition. Every assistant does this. It is the baseline.
Builds across sessions · Requires consent · More advanced
Episodic memory
A persistent store of facts, preferences, and context extracted from past sessions — written, stored, and retrieved. Significantly more complex to build well than in-session context.

What gets stored: language and format preferences, named relationships ("Mummy has diabetes"), recurring topics, correction history, past queries with dates.

How it fires: when a new query is relevant to a past memory, JioBharatIQ retrieves and applies it — without the user having to re-explain. The relevance gate matters: not every memory fires, only when confidence is high.

User control: explicit consent at Session 3. User can view, edit, pause, or delete what is stored. Memory that cannot be controlled cannot be trusted.
Memory is distinct from signals — signals are read, memory is written and retrieved. In-session context requires no infrastructure beyond the active session. Episodic memory requires a persistent store, a write pipeline, a retrieval mechanism, and a consent layer.

5 · Execution
Where we are,
and what ships next
Personalization is being built in phases, anchored to the user arc. The first milestone — Friends and Family — covers the Know You stage: Day 0 to Day 30, approximately 5,000 users, 32 use cases across 9 experience moments. The goal is to validate the full personalization arc before scaling.
Now · Alpha
Know You
~500 RCP employees. Full signal stack active. Core personalization validated internally.
Next · FnF
Know You · expanded
~5,000 users. Day 0 to 30. Memory with consent, home shifts, re-engagement via right channel. Full arc validated before scaling.
Next
Remember You
Cross-session memory deepens. Preference model builds. Ecosystem loop opens.
Later
Anticipate You
Pattern-based proactivity. Household model. Pre-emptive surfacing.
Destination
N=1
All tracks converged. Individual model complete. Experience built for this person.
What ships in FnF
Day 1 experience
Language from SIM, time-aware greeting, occupation-matched prompts, TTS auto-play on low-cost devices, regional seasonal context card. Non-Jio users get a warm fallback — no language picker ever shown. P0
First conversations
Register mirroring (Hinglish in, Hinglish out), literacy-adaptive response length, voice brevity for hurried users, emotional listening, language lock that never drifts mid-session, image plus voice for contextual queries. P0
Memory and consent
Memory gate at Session 3 in plain Hindi — Always / Just today / Never. Pipeline-enforced. Post-consent: preference recall applied silently, correction handling with user in control, full memory visibility and edit access in My Preferences. P0
Returns and re-engagement
Returns greeted with last context, not a generic welcome. Incomplete tasks surface as a card. Re-engagement notification at Day 3 references the actual last session. WhatsApp fallback at Day 7 if no PN opt-in — single message, then done. P1
By Day 30, Sunita's Know You arc is complete: language locked, register calibrated from Turn 1, memory active with consent given in plain Hindi, home re-ranked to her actual usage, preferences stored and editable, re-engagement via the right channel at the right moment. 32 use cases delivered. Ready for Remember You.
