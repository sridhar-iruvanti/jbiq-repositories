JioBharatIQ — Metrics Tree

A metrics-design artifact. Pure product thinking, no milestone scaffolding. Layers organised by user experience, not by internal pod taxonomy.

Owner: Sridhar · Last updated: 2026-05-09

Method

Working backwards from the product, not forwards from milestones. Layers map to what the user experiences, not to internal team boundaries.

The product is a personal AI for India that makes three claims: 1. Knows you — language, context, history 2. Knows what you need right now — proactive, situational 3. Does the work — completes tasks, doesn't suggest

The product is working when: A user opens JBIQ, gets something done, comes back tomorrow without being pushed, and the next session starts smarter than the last. Repeat that across 1.4B Indians, in 12 languages, across 12 domains.

Every metric in the tree must connect — mathematically or causally — back to that statement.

Activity Units

All units anchored at the monthly level for consistency. Daily snapshots (DAU, DQU) are derived from these monthly bases when needed for the L0 stickiness ratio — they are not primary units to track.

Unit Definition Role
MAU Users who opened the app in last 30 days (rolling) Funnel diagnostic only — opened ≠ engaged
MQU Users who sent ≥1 query in last 30 days (rolling) The activity unit · L0 denominator. Anchors engagement and retention metrics.
MTU Users who completed ≥1 useful task in last 30 days (rolling) Monthly value-delivered unit — captures value, not just engagement

Note on daily snapshots: Active Habit Rate (L0) = Organic DQU ÷ MQU is a daily-stickiness ratio. Daily querying users (DQU) are derived from MQU on a per-day basis — not tracked as a separate primary unit.

For deeper diagnostics, use per-query views, not per-user counts:

Query → Resolved   (Task Resolution Rate)
Resolved → Satisfied   (User Satisfaction Rate)
Useful Task Rate = Resolved × Satisfied   (per-query)

L0 — The Single Test (paired)

A single number is too lossy for a product whose promise is "loop and work." Use a paired north star. Both must move together.

Metric Definition What it tests
Loop Active Habit Rate Organic DQU ÷ MQU — daily-stickiness anchored on querying users, push-attributed returns excluded Did the product earn the user, or did push pay for the visit?
Work Useful Task Rate % of queries that resolved AND user signaled value Did the AI actually deliver something useful?

Composite (rollup): Compounding Habit Index = Active Habit × Useful Task. Useful for one-number reporting; never a substitute for the pair.

L1 — The Decomposition

L1 of Active Habit Rate (causal drivers, not multiplicative)

  Activation              = % of installs that complete a useful task within window (D7 default)
  Engagement Depth        = queries-per-DQU-per-day · active-days-per-week (deeper = stickier)
  Retention               = % of activated users who fire ≥1 organic query at D7
  Loop Self-Sufficiency   = Organic returns ÷ Total returns
  Personalization Lift    = uplift in retention from Personalization Resonance (Layer 2)
  Virality                = New installs from referrals ÷ existing users

Engagement is a driver, not a component: deeper engagement today → higher likelihood the user is tomorrow's Organic DQU. It belongs in the causal model even though it doesn't appear in the L0 ratio mathematically.

Returns decomposition (sister metrics, all in Layer 1)

Metric Definition Where in tree
Active Habit Rate Organic DQU ÷ MQU L0
Total Return Rate (Organic + Push-attributed) ÷ MQU L1
Loop Self-Sufficiency Organic ÷ Total L1
Push-attributed Return Rate Push-driven ÷ Total L1
Habit Formation Rate % of Prompted users → Organic within 60d L1

L1 of Useful Task Rate (mathematical identity)

Useful Task Rate = (Intent × Routing × Execution × Production Quality Floor) × User Satisfaction
                =  Task Resolution                                            ×  User Satisfaction

Where each factor lives (single source of truth — referenced, not duplicated): - Intent / Routing / Execution → Layer 4 (Task Delivery) L1 - Production Quality Floor → Layer 5 (Quality) L0 - User Satisfaction → Layer 1 (User Loop) L1, Group E (Sentiment + Value)

User Satisfaction is computed from a basket of behavioural + explicit signals (defined once in Layer 1): - No rephrase within 60s (didn't have to re-ask) - No thumbs-down on the response - Conversation continued OR user returned to that domain within 24h - No "still didn't help" / restart pattern - Plus explicit signals where present: thumbs-up, NPS, survey ratings

The 7 Layers — Organised by User Experience

Each layer answers a question the user would actually ask of the product. Internal taxonomy (Vertical / Signature / Core) is deliberately not a layer — it's a cross-cut. Bharat resonance is also not a layer — it's a parallel framework that inherits from this tree (sliced by Cohort A–E) and adds qualitative resonance metrics. See bharat-metrics.md.

Layer 4 — The Task Delivery

Did the AI do what I asked? · The orchestrator owns "did the system do what was asked of it?" — not "did the user feel served." The user-need-met question lives at the product L0 (Useful Task Rate = this layer's L0 × User Satisfaction from Layer 1).

Latency note: Layer 4 owns modality-agnostic task speed (TTFT, overall E2E). Voice-specific latency (E2E voice ≤1.5s, barge-in ≤300ms) lives in Layer 3 (Conversation) Voice path L1 — that's a conversation-feel concern, not a task-execution concern. Underlying SLO compliance rolls up to Layer 6 (Platform).

Level Metric Why
L0 Task Resolution Rate (system-side: task reached a resolved state) Layer 4's contribution to Useful Task Rate

L1 — Accuracy Execution Success Rate (skill ran without error) Right skill, broken execution = same failure
L1 — Accuracy Multi-step Task Success Rate Agentic chains are fragile
L1 — Speed TTFT p95 (time to first token) Voice has zero latency tolerance
L1 — Speed E2E Latency p95 (full response time) Complete response in budget

L2 Per-domain task completion Which domains are weakest?

Out of the Product Tree

These are real, measurable, and important — but they're infrastructure, GTM, or operations, not product metrics. They live in parallel tracks; the product tree references them but doesn't own them.

Growth (GTM track)

Acquisition, CAC, channel mix, paid attribution. GTM produces installs → consumed by Activation Rate (Layer 1 L1). Product earns advocacy → Virality and referral attribution (Layer 1 L1) flow back. The product earns advocacy; the product does not own acquisition.

Distribution (GTM track)

Channels through which users reach the product — Jio retail, MyJio, JioFiber, organic, paid, referral. Per-channel cohort outcomes are GTM concerns. The Cohort cross-cut (Jio/non-Jio, urban/Tier-2/3) lets the product tree slice by distribution-derived segments without owning channels.

Data (Foundation Capability track)

Instrumentation, dashboards, joins, freshness, self-serve analytics. Capability metrics: Insight Velocity (median time question→answer), dashboard coverage, cross-source join freshness. Data is how we measure the product. It is not the product.

A/B Experimentation (Foundation Capability track)

Causal inference engine. Capability metrics: experiment velocity, time-to-significance, experiment coverage, holdout-cohort discipline. Distinct from Eval CI/CD (Layer 5 — pre-deploy offline gating). Currently blocked at FnF (GrowthBook InfoSec gate); all FnF metric movements are correlational.

Unit Economics / Cost (Operations track)

Cost of serving the product. Tokens consumed per user per day, cost per query, cost per task, cost per active user per month, LLM model-mix cost, voice pipeline cost, per-domain cost-per-task, per-language cost. Critical to business viability but doesn't measure whether the product is working — the product earns engagement; the operations layer pays for it.

Vertical Portfolio Management (Strategy / Content track)

The Vertical / Signature / Core taxonomy is internal — users don't experience it. Portfolio metrics live here: count of SEs at L2+ maturity, count at L3 (signature), idea→live velocity, per-SE retention (as a portfolio diagnostic), concentration metric (% of value from top 5 SEs). These inform what to build next; they don't measure whether the product is working today.

User Sentiment & Resonance (redistributed)

Components folded into product layers: - NPS, NPS verbatim, free-text sentiment, FGD findings, trust signals → Layer 1 (User Loop) - Brand-voice adherence, language authenticity → Layer 5 (Quality) - Memory-trust signals → Layer 2 (Personalization) - Persona resonance, Sunita/Raju Score, BPC → bharat-metrics.md

Three design choices worth defending

1. Paired L0, not single. Choosing one of {Active Habit, Useful Task} would compromise the product. A high single-metric organisation can hit it by failing the other half. The pair forces both.

2. Layers organised by user experience, not internal pod taxonomy. The user doesn't experience "Vertical Experience" or "Signature Experience" — they experience "did it work, did it know me, did it talk well." Organising layers around user-experienced concepts forces the metrics to test what users actually feel, not what teams ship. Internal taxonomy (Vertical / Signature / Core) is real and useful for portfolio management — but it lives as a cross-cut and a Strategy track, not as a layer.

3. Personalization elevated to its own layer (Layer 2). N=1 personalization is one of the 5 Key Bets. Burying it inside Memory + scattering it across User obscured a strategic bet. Layer 2 with Personalization Resonance Rate as L0 makes the bet visible and movable. Sub-areas (Memory-driven, Surface-driven, Language-driven, Identity-driven, Adaptive) are L1 — each independently movable.

4. Cohort A–E as cross-cut, Bharat as parallel framework — not a separate layer. Earlier we considered making Bharat-First Adherence a separate Layer 8 with a Bharat Persona Composite (BPC) L0. The simpler answer: cohort cuts on Active Habit Rate ARE the behavioural resonance test. If Cohort D users keep returning organically, the product is resonating with them — by behaviour, the most reliable signal. A "Bharat composite" layer was double-counting what the cohort cut already shows. Instead: Cohort A–E (per jbiq_user_cohort_gtm__v1.docx) is the cross-cut applied to every metric in the tree. Cohort Variance (max − min Active Habit Rate across A–E) is the strategic diagnostic, kept at Layer 1 L2. Soft, qualitative resonance metrics ("feels native vs translated", persona-fit feel, cultural relevance, FGD themes per cohort) live in bharat-metrics.md as a parallel periodic framework — distinct from the always-on product tree.
