Product Promise

The product is working when a user opens JBIQ, gets something done, comes back tomorrow without being pushed, and the next session starts smarter than the last. Repeat across 1.4B Indians, 12 languages, 12 domains.

Knows you — language, context, history  ·  Knows what you need right now — proactive, situational  ·  Does the work — completes tasks, doesn't suggest

Paired North Star

Two metrics. Both must move together. Neither alone is sufficient.

Loop
Active Habit Rate
Organic DEU ÷ MEU
Push-attributed returns excluded. Did the product earn the return, or did push pay for it?
Work
Useful Task Rate
% tasks resolved AND user signaled value
Did the AI deliver something useful? Composed from Layer 4 L0 × Layer 5 L0.
Composite: Compounding Habit Index = Active Habit Rate × Useful Task Rate  ·  One-number reporting only, never a substitute for the pair.

Layer Design Principles

1–5 User-backwardsUser experienceWhat the user felt, did, or returned forCannot be gamed by system improvements that don't reach users

Activity Units

MAU— opened the app in last 30d
  └── MEU— query OR audio/video ≥10s in last 30d  (MQU ∪ MCU)
        ├── MQU— ≥1 query sent (text / voice / image). All queries are tasks. MQU ⊂ MEU.
        └── MCU— ≥1 audio/video played ≥10s. Card taps are surface events, not MCU.
UnitDefinitionDenominator forNote
MAUOpened app in last 30 daysFunnel diagnostic onlyOpened ≠ engaged
MEUQuery OR audio/video ≥10s in last 30 daysActive Habit Rate · retention · engagementCaptures content-heavy verticals (Devotion, Cricket, News)
MQU≥1 query in last 30 days. MQU ⊂ MEU.Query-depth analyticsVoice vs text split, per-language, per-skill
MCU≥1 audio/video ≥10s in last 30 days. MCU ⊂ MEU.Content analyticsCompletion rate, content-to-query conversion
Useful Task — a task that resolved AND the user signaled value. Derivable from events.
ALL of: no rephrase within 60s · no thumbs-down · no restart pattern.
Plus ≥1 positive: conversation continued · domain return within 24h · explicit thumbs-up.
A query is a task. A task is not always a single query — one user intent can span multiple queries.

Real, measurable, important — not measures of whether the product is working for users.

Glossary

TermDefinition
L0The single primary metric for a layer — the outcome that defines whether the layer is doing its job. One per layer. Non-negotiable.
L1Primary drivers — the metrics that cause or compose the L0. What pod leads own and optimise. Independently movable.
L2Diagnostics — signals that explain why an L1 moved or didn't. Leading indicators, input metrics, operational health checks. Never in a leadership review.
MAUMonthly Active Users — users who opened the app in last 30 days. Funnel diagnostic only. Opened ≠ engaged.
MEUMonthly Engaged Users — users who sent ≥1 query OR played audio/video ≥10s in last 30 days. Primary engaged base. MQU ∪ MCU.
MQUMonthly Query Users — users who sent ≥1 conversational query (text / voice / image) in last 30 days. MQU ⊂ MEU. All queries are tasks.
MCUMonthly Content Users — users who played ≥1 audio or video item for ≥10s in last 30 days. MCU ⊂ MEU. Card taps are not MCU.
DEUDaily Engaged Users — daily snapshot of MEU. Used in Active Habit Rate numerator (Organic DEU ÷ MEU).
DTUDaily Task Users — daily snapshot of MTU. Used in task-specific daily stickiness calculations.
Active Habit RateOrganic DEU ÷ MEU — push-attributed returns excluded. Product L0 (Layer 1). Tests whether the product earned the return.
Useful Task Rate% of tasks that resolved AND user signaled value. Product Work L0. Composed from Layer 4 L0 × Layer 5 L0.
Useful TaskA task that resolved AND the user signaled value. Signals: no rephrase within 60s, no thumbs-down, no restart, plus ≥1 positive (continued / domain return 24h / thumbs-up).
TaskA user-initiated interaction where the user directed intent at the AI — query (text/voice/image) or structured skill action. A task is not always a single query; one intent can span multiple queries.
UCPUser Central Profile — the user's data profile, populated from JioID and session behaviour. UCP parameter coverage = % of attributes populated at session start. UCP utilisation ratio = attributes used ÷ available per session.
JioIDReliance Jio user identity — the source of pre-loaded context for Jio users on Day 0.
Warm startA session where the product already knew the user before they said anything — correct language auto-served AND ≥1 UCP attribute applied AND JioID context loaded (for Jio users). All three must hold.
Cold startA session with zero UCP context loaded — generic language, generic home, no prior context. The failure state of the identity layer.
Personalisation Resonance Rate% of sessions where the product demonstrated it knew the user. At least ONE of: correct language auto-served · prior context applied without re-explanation · personalised surface element engaged · proactive suggestion accepted.
Loop Self-SufficiencyOrganic returns ÷ Total returns. What share of returns are unprompted. High = product earning the habit. Low = comms propping up the loop.
Habit Formation Rate% of push-prompted users who become organic returners within 60 days. Tests whether comms builds the habit or just sustains dependency.
Cohort A–E5 user cohorts per jbiq_user_cohort_gtm__v1.docx — each encapsulating language, device tier, geography, and segment. The primary Bharat-first slicing dimension.
Cohort Variancemax(Active Habit Rate across A–E) − min. High variance = product winning unevenly. Even a healthy average can hide one cohort failing.
Signature Experience (SE)A vertical experience that passes all 3 qualification benchmarks — proprietary data binding, loop-forming threshold, cultural irreplaceability. Score 0–3; only 3/3 qualifies. Re-baselined quarterly.
BPCBharat Persona Composite — weighted average of Cohort Score across Cohorts A–E. See bharat-metrics.md.
NPSNet Promoter Score — will the user recommend the product?
ASRAutomatic Speech Recognition — converts voice input to text.
WERWord Error Rate — ASR accuracy measure. Lower is better.
TTSText-to-Speech — converts text responses to audio output.
MOSMean Opinion Score — TTS naturalness rating on a 1–5 scale. Validated by native-speaker blind evaluation.
VADVoice Activity Detection — detects when the user is speaking vs silent.
TTFTTime to First Token — latency from query submission to first response token. Key responsiveness signal.
E2E LatencyEnd-to-end latency — time from query to complete response delivered.
p9595th percentile latency — the latency value that 95% of requests fall under. The SLO target percentile.
