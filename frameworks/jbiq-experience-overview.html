01 — Context

Who JBIQ is built for

The Bharat B/C/D user. Not the English-first, app-native metropolitan user — a different set of constraints, intentions, and digital behaviours that shape every product decision downstream.

📱
Phone is the only screen
No laptop, no tablet. Everything — entertainment, commerce, health, finance, communication — happens on a single Android device, often shared with family.
Mobile-only
🎙️
Voice over text
Text input is slow, error-prone, or uncomfortable in local languages. Voice is the natural interaction mode — WhatsApp voice notes, YouTube voice search, spoken queries.
Voice-first
🗣️
Hindi + regional, not English
12 scheduled languages, multiple regional variants. Bhojpuri, Maithili, Marathi, Tamil, Bengali — the product must work in the user's actual mother tongue, not a Hindi translation.
Mother tongue
🏘️
Tier 2, 3, and rural
Outside the top 8 metros. Variable connectivity. Jio network reach is the distribution edge — JBIQ runs where competitors don't have reliable users.
Tier 2–3, rural
💡
Practical, not aspirational apps
The primary apps used: WhatsApp, YouTube, JioTV, JioCinema. App-first behaviour doesn't exist — the habit is content-first and communication-first. Low tolerance for friction.
Content-first
🤝
Trust is earned, not given
No second chances easily. The first session either delivers immediate value or the user doesn't return. JBIQ must be useful before it asks anything of the user.
Value-first

03 — Interaction Layer

Conversation & Multimodal

The AI interface across text, voice, image, and video. Six voice states define the full arc of a conversation — from idle presence through task completion. Input and output are both multimodal at GA.

Voice States — Full Arc
Idle
Ambient presence. JBIQ is ready but not active. Appears on home surface and in conversation bar.
Listening
Microphone open. JBIQ is receiving the user's voice input. Animates with audio waveform response.
Thinking
Processing state. Query received, generating response. Shown between listen and speak transitions.
Speaking
TTS playback. JBIQ is delivering its voice response. Screen response renders in parallel.
User Speaking
Conversational turn — user is mid-speech. Distinct from listening; indicates a two-way live exchange.
Complete
Task done. Signals successful completion — answer given, action executed, or task resolved.
Conversation Principles
Rule 01
Voice is always standalone-complete
Every TTS response must be meaningful without the screen. Screen mirrors or extends — never required to understand the answer.
Rule 02
One clarification at a time
Never ask more than one follow-up question in a row. A second clarification without an answer in between breaks the conversational contract.
Rule 03
Domain register holds across input modes
Whether the user types, speaks, or sends an image — the AI stays in its domain character. Input modality doesn't change persona.
Rule 04
Multimodal input: text + voice + image
At GA: typed query, voice query, image input (product photo, medicine label, document scan). Output: voice + text + rich card + action.

04 — N=1 Engine

Personalisation

JBIQ adapts to the individual user across two axes simultaneously: domain character changes based on which domain you're in, and register adapts based on who you are. The N=1 layer sits above both and builds across sessions.

N=1 Learning Arc
1
Sessions 1–5
UCP Defaults
Language preference, rough interest signal from Jio profile, location. JBIQ responds with domain defaults + persona archetype register.
Archetype-driven
6

Memory Builds

Observation-driven

Predictive

Onboarding just completed. JBIQ uses UCP defaults + onboarding inputs to generate the first personalised home.
D7

Early signal from first week of use. Dominant domains surface. Register begins calibrating toward actual usage pattern.
D30

Habit formed. Memory arc is in sessions 20+ territory — proactive suggestions, pre-loaded domain context.
GAP

User returns after a gap. JBIQ acknowledges return, recaps recent relevant events in key domains, soft re-entry.

POW

High-frequency, multi-domain user. JBIQ surfaces advanced features, proactive digest mode, reduced friction everywhere.
05 — Retention Architecture

Hooks & Loops

The mechanisms that bring users back and deepen usage over time. Hooks are external triggers that re-enter the user. Loops are in-conversation patterns that extend a session and seed the next one.

The Engagement Loop
1
Entry
User arrives from any surface — home, push notification, JioCinema, deep link. Intent is narrow: single query or check.
Home Push JioCinema Deep link
2
Task Resolution
Query answered via domain persona with correct primitive combination. Voice + screen. Task is complete — user has what they came for.

3

Immediately post-task: a single relevant next action or suggestion. Not a prompt to stay — a genuinely useful extension of what the user just did.

User takes the next step. Second turn. Could be same domain (follow-up query) or cross-domain jump (cricket score → JioCinema highlights).

Signature experiences need named sources
Every domain has at least one signature experience. A signature experience is only a moat if it has a named data or integration source. Without it, it's an everyday use case any LLM can do.
2P integrations are the strategic dependencies
JioCinema, JioMart, JioHealth — these are what make JBIQ different from a generic assistant. Their APIs being live at GA is the critical path, not model quality.
3P partners enable transaction depth
Pilgrimage booking, doctor consultation, job application, NCS matching — these transactions require 3P partnerships. Partner portal (Sushant's pod) is the onboarding path.

Architecture Note
JBIQ is one engine — not seven products. A shared conversation engine, 7 domain knowledge configurations, a per-user register adaptation layer, and a primitive rendering layer. The complexity sits in the signature experience integrations and the N=1 memory architecture — not in building separate domain models.
